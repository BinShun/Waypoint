# Waypoint — Final Design Synthesis

> Status: **confirmed design contract** (2026-09-25). This document is the
> single product direction for the Waypoint redesign. It is not a UX report
> and not one of several options — it is the direction the builder executes.

**产品定位**：销售工作台 + 可保存的业务列表 + 相互关联的记录工作区。
保留现有全部业务能力，重新组织信息和操作。

---

## 1. Core design principles

1. **工作入口与业务导航并存。** Today 回答"现在该做什么"；Customers、People、Opportunities、Interactions 回答"我要查找和处理什么"。不强迫所有工作从首页开始。
2. **列表与记录分工。** 列表负责检索、比较、选择和批量处理；记录负责理解背景、阅读历史和推进业务。不能用一种页面形态包办两者。
3. **保持上下文，贯通关系。** 从客户进入联系人、商机或互动时，始终知道当前客户和来源；相关记录可以直接到达，不必退回全局重新寻找。
4. **先呈现判断所需的信息，再展开完整内容。** 概览提供有限摘要与入口，不复制所有明细；完整 MOM、组织结构和历史按需阅读。
5. **统一操作规则，不强制统一布局。** 相同操作具有相同含义，但行动队列、业务列表、销售看板和活动历史各自服务不同任务。
6. **未知保持未知。** 部门、汇报关系、负责人尚未确认时允许留空。建议值不是业务事实，不能通过显示方式或改名动作悄悄变成已核实。
7. **高频操作简短，重要变更明确。** 维护少量信息不必进入大型表单；批量更新、删除、关联变更和离开未保存表单必须可理解、可追踪，并尽可能可恢复。

## 2. Final information architecture

### 全局导航

- **Today**：我的行动、需跟进事项、日历。日历保留独立访问路径，归属于工作入口。
- **Customers**：客户组合管理及客户记录。
- **People**：跨客户联系人检索与维护。
- **Opportunities**：Pipeline 推进、商机比较与预测。
- **Interactions**：互动记录检索、MOM 阅读与录入。
- **参考能力**：Products、Insights。
- **系统能力**：AI Tasks、Admin、Settings，按权限开放。
- **全局工具**：可见的搜索入口、快捷创建、最近访问；快捷键是加速方式，不是唯一入口。

### Customer Detail

固定提供职责明确的记录分区：

- **Overview**：当前业务状况与下一行动。
- **Activity**：互动、备注、行动及业务变更的时间历史。
- **People**：联系人列表、Departments 管理入口、组织结构浏览。
- **Opportunities**：该客户的商机。
- **Systems & Products**：现有系统、产品与相关业务信息。
- **Files**：文件和附件。

审计按权限进入变更历史，不再与文件混为一种内容。客户全部行动从 Overview 和 Activity 可直达 Today 的该客户行动列表。

**最终取舍：保留对象导航和必要的记录分区；取消强制"无 Tabs、全三栏、全部内容单页展开"的方向。部门保留为客户 People 下的可管理模块，而不是降级为一个不可管理的下拉字段。**

## 3. Key screen direction

### Today — 执行工作，不是查看仪表盘

1. **范围**：默认我的执行与跟进事项；有权限时切换团队范围。
2. **行动队列**：按逾期、今日、即将到期组织，展示客户、相关商机、执行人和 Tracker。
3. **时间与关注事项**：日历中的会议，以及有明确业务依据的待跟进事项；不堆叠无操作出口的指标。
4. **直接处理**：完成、改期、记录跟进、进入相关记录。处理后队列与关联记录同步更新。

### Customers — 管理客户组合

1. **工作视图**：默认我的客户，支持个人及授权共享的 Saved Views。
2. **浏览主体**：默认业务列表，比较负责人、健康状态、商机情况、最近活动和下一行动；支持列配置与排序。
3. **维护入口**：创建客户、批量更新有权限的字段、导出当前查询结果。
4. **进入记录**：名称打开完整客户记录；预览是独立操作。返回时恢复原来的查询、排序和浏览位置。

### Customer Detail — 理解一个账户并推进业务

1. **记录身份**：明确客户、Primary BD、Primary SA、业务状态，以及记录互动、创建商机、添加行动的入口。
2. **默认 Overview**：集中回答"谁负责、什么正在推进、谁关键、下一步是什么"，只提供关键商机、联系人、行动与最近活动的有限摘要。
3. **完整工作分区**：Activity、People 等承接大量明细。概览中的"查看全部"进入对应范围，不复制另一套数据。
4. **关联操作**：从当前客户发起创建自动带入客户；打开相关记录保留来源。概览摘要不能代替完整行动清单。

### People — 查找、理解和维护关系

1. **统一联系人列表**：全局与客户内共用搜索、筛选、排序、列配置及批量维护能力；客户内固定客户范围。
2. **维护关系信息**：部门、客户层分类、立场、腾讯关系负责人、最后接触等可组合查询；支持批量设置部门、负责人和分类。
3. **Departments 管理**：客户 People 下有明确入口，支持创建、改名、核实、停用和查看成员。人员分配时搜索本客户部门，也可留空；更名不改变部门身份及关联。
4. **理解具体关系**：联系人记录呈现参与的商机、互动与行动；组织图作为按需浏览方式，只展示已记录的汇报关系，支持展开分支。

腾讯关系负责人可输入新姓名并记录为腾讯成员，不要求创建登录账号，也不因此授予系统权限。

### Opportunities — 推进交易与比较管线

1. **默认工作范围**：我的进行中商机，提供保存视图。
2. **两种任务模式**：Pipeline 看板用于阶段推进；列表用于比较、预测及批量维护。两者共享筛选条件和记录。
3. **商机记录**：突出阶段、金额、概率、预计关闭日期、负责人、相关联系人角色及下一行动。
4. **推进过程**：阶段变更执行现有业务校验；会议、承诺和行动直接关联商机，而不只出现在客户总历史中。

### Interactions — 可检索的业务记忆

1. **检索入口**：按客户、商机、参与人、日期和类型组合查找，支持检索 MOM 正文。
2. **默认浏览**：使用简明记录列表，完整 MOM 在打开记录后阅读，不把所有正文常驻展开。
3. **统一录入**：清楚区分 Details / MOM 与 Outcome，保留 Workshop 等互动类型；上下文提供客户、参与人和商机选择。
4. **形成后续工作**：同一流程可添加多条真实 Next Steps，各自指定执行人、Tracker 和期限。优先关联已有商机，明确选择"新建"才创建；没有商机或行动也能记录互动。

## 4. Final interaction model

| 项目 | 最终规则 |
|---|---|
| **Navigation** | 全局业务入口稳定；记录及分区可直接链接。返回列表恢复浏览状态，不自动复活编辑状态。 |
| **Search** | 全局搜索负责跨对象发现；列表搜索负责当前范围查找。两者都保留可见入口，搜索结果遵守客户访问权限。 |
| **Filter** | 统一字段、操作符和值的组合条件，支持 AND / OR、排序、列配置及 Saved Views。统计是结果摘要，不再承担整个筛选系统。 |
| **Preview** | 点击名称进入完整记录；明确的预览操作打开一层快捷查看。禁止默认选中首条、强迫常驻详情或不断叠加抽屉。 |
| **Edit** | 简单字段可明确进入并提交局部编辑；复杂修改使用显式保存、取消。分类选择不得顺带提交其他未保存字段。 |
| **Delete** | 日常移除优先可恢复归档；永久删除单独确认并保留管理员权限边界。归档不能成为绕过现有权限的通道。操作前说明关联影响，不能静默级联删除。 |
| **Relationships** | 同一业务事实只保存一次，通过关联在客户、联系人、商机和行动中呈现，不复制多份历史。 |

### 必须明确的行为

- **视图与选择分离**：保存视图保存查询、排序和列配置，不保存临时勾选或编辑状态。共享视图不扩大他人的数据权限。
- **批量操作有范围**：明确区分"本页所选"与"全部匹配记录"；执行前显示数量，结果逐项说明成功、失败和原因。
- **离开未保存表单**：提供"保留草稿并离开 / 放弃修改 / 继续编辑"。返回默认阅读，草稿由用户显式恢复；不静默丢弃或自动提交。
- **关键动作可发现**：鼠标、键盘、触屏均能访问，不依赖 hover、双击或隐藏暗号。
- **复合录入明确提交**：记录互动时先确认将创建和关联哪些记录；整体成功才显示已保存。失败保留输入，重试不重复创建。

### 关系契约

- **Customer → Department / Person**：部门属于客户；联系人可以没有部门。部门名称已核实，不代表其中每个人的归属已核实。
- **Person ↔ Opportunity**：联系人可参与多个商机，商机内角色单独记录，不用客户层分类自动代替。
- **Interaction → Customer / Participants / Opportunities**：互动属于客户，可关联参与人及相关商机；没有商机关联也合法。
- **Next Step → Customer / Opportunity / Source Interaction**：行动是独立可跟踪记录，客户必需，商机和来源互动可选。执行人与 Tracker 分离，Tracker 仍遵守该客户 Primary BD/SA 规则。
- **稳定身份**：更名不改变记录身份。部门改名不是人员迁移；停用后不再供新分配，历史归属保留。真正迁移成员是另一项明确操作。

## 5. Scale test

**以下是实现验收条件，不是对现有系统性能的通过声明。**

| 规模 | 必须成立的工作方式 |
|---|---|
| **500+ Customers** | 保存视图及组合查询缩小范围，不翻阅数百张卡片；汇总覆盖完整权限内结果；打开记录再返回不丢位置。 |
| **5,000+ People** | 列表分页浏览，部门和负责人可搜索；明确范围的跨页批量操作。同名联系人不混淆，组织图按客户及分支展开。 |
| **10,000+ Interactions** | 搜索完整历史与 MOM 正文，按客户、商机、参与人和时间组合筛选；初始仅加载摘要，全文按需读取。 |

共同验收要求：

- 初始读取有边界，不能先传输全部数据再仅在界面隐藏；看板和活动历史同样需要分批读取。
- 搜索、排序、统计与导出针对完整匹配结果，不只针对当前已加载页面。
- 查询变化不能误保留旧的全选范围；批量执行可查看进度，处理权限变化、并发修改和部分失败。
- 离线、保存失败与同步冲突有明确状态，不能把本地暂存显示为服务器已保存。
- 在约定设备及网络基准下，以首屏可操作不超过 2 秒、搜索及筛选响应 P95 不超过 1 秒为验收目标，实际测试后判定。

## 6. BUILD BRIEF

### KEEP

- 客户、联系人、部门、商机、互动、行动之间的真实业务内容。
- 客户访问范围、Primary BD/SA、执行人与 Tracker 分工及管理员删除边界。
- 客户级部门管理、无需登录账号的腾讯关系负责人。
- Decision maker / Blocker / Influencer 三类联系人分类。
- MOM、Outcome、Workshop、日历、产品、系统、文件、审计、Insights 和 AI 能力。

### REMOVE

- 默认大卡片墙、重复统计筛选墙和常驻完整 MOM。
- 解释设计理由的长段落、需要学习暗号的状态表达。
- hover-only 关键动作、默认自动打开首条记录。
- 隐式提交、导航后残留编辑态、各页面含义不同的同类操作。

### REDESIGN

- 搜索、组合筛选、Saved Views、分页、列配置及批量操作。
- Customer Overview 与完整记录分区的职责边界。
- People 列表、Departments 管理及组织图之间的关系。
- 商机内联系人角色，以及互动、商机、行动的双向可达关系。
- 从记录会议到生成多条行动、再到 Today 跟进的完整流程。
- 草稿、归档、永久删除、冲突及批量失败的处理规则。

### DO NOT DO

- 不以调整颜色、间距或容器代替信息架构重构。
- 不一律禁用 Tabs，不一律三栏，也不把日历和 Pipeline 强行变成表格。
- 不把部门降级成无法管理的字段，不把职位推断当作组织事实。
- 不用显示名称作为关联身份，不因命名负责人而创建账号或授予权限。
- 不通过删掉业务能力换取简洁，不用少量演示数据证明规模可用。

**实施顺序**：先冻结关系与交互契约，再统一发现和列表能力，随后完成 Customer / People，贯通商机、互动与行动，最后完成 Today 及规模验收。

**最终验收主链**：找到客户 → 定位并维护关键联系人 → 记录 Workshop 与 MOM → 关联已有商机 → 创建两条有负责人和期限的行动 → 在 Today 跟进 → 从客户、联系人和商机读取同一份关联历史。
